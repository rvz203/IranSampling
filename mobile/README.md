# اپ میدانی ایران سمپلینگ

اپ مشترک اندروید و iOS برای سرپرست و سمپلر، متصل به همان API و PostgreSQL پنل وب. ادمین در **تیم ← مشخصات همکار ← تنظیم نام کاربری و رمز** حساب را مدیریت می‌کند. ورود با نام کاربری یا ایمیل انجام می‌شود. تغییر رمز، نشست‌های وب و موبایل همان حساب را لغو می‌کند.

## مسیر کار

1. ادمین در پنل وب شیفت را باز می‌کند و از **ویرایش برنامه و تیم** ساعت کار، ناهار، سرپرست و سمپلرها را تعیین می‌کند. ساعات به وقت تهران است و برای اعضای همان شیفت اعمال می‌شود.
2. کاربر با حساب خودش وارد اپ می‌شود. اپ فقط شیفت‌های اختصاص‌یافته و اطلاعات مجاز کاربر را از سرور می‌گیرد.
3. کاربر در محدودهٔ نقطه با GPS ثبت ورود می‌کند و می‌تواند با **ورود و شروع اشتراک**، اشتراک همان شیفت را هم تأیید کند.
4. در ساعات کار، هدف ثبت یک نمونه در هر بازهٔ ۳۰ ثانیه‌ای است. در ناهار اپ نمونه‌ای ذخیره یا در صف نمی‌گذارد و پس از استراحت همان اشتراک ادامه می‌یابد. برنامهٔ آخرین دریافت‌شده هنگام قطعی اینترنت اعمال می‌شود. سرور بازه‌های معتبر را هنگام همگام‌سازی دوباره بررسی می‌کند. سرپرست «موقعیت تیم» را می‌بیند و ادمین علاوه بر نقشهٔ زنده، تب **تاریخچه موقعیت** هر شیفت را دارد.
5. سرپرست آمادگی را تأیید می‌کند. سمپلر موجودی، توزیع، مشکل و عکس ثبت می‌کند. عکس‌ها از دوربین یا گالری به صف ارسال می‌روند. سرپرست می‌تواند مشکل را پیگیری و گزارش را تأیید یا برای اصلاح بازگرداند.
6. در ساعت پایان برنامه یا با دکمهٔ **پایان شیفت**، سرور حضورهای باز را با برچسب پایان خودکار می‌بندد و خلاصهٔ حضور، زمان کار، توزیع، موجودی، عکس و مشکلات را ثبت می‌کند. برای گزارش قابل تأیید، عکس اجرا و توضیح ثبت کنید. تأیید نهایی به تطبیق موجودی و رفع مشکلات فوری نیاز دارد.

SQLite نمونه‌ها و صف را بین باز و بسته شدن اپ نگه می‌دارد. فایل عکس تا تأیید سرور در فضای خصوصی اپ باقی می‌ماند. صف بر اساس سرور و حساب جدا می‌شود. با اتصال دوباره در اپ یا انتخاب «همگام‌سازی اکنون»، ارسال ادامه می‌یابد. در پس‌زمینه وظیفه مکان نمونه‌های GPS را هم به‌صورت دسته‌ای ارسال می‌کند. نمونه تکراری و تلاش دوباره برای همان عکس در سرور رکورد جدا ایجاد نمی‌کند. وضعیت موارد ردشده در صف قابل مشاهده است.

برای شروع اشتراک و ثبت ورود، خروج، موجودی، مشکل و گزارش ارتباط سرور لازم است. اپ نسخه ذخیره‌شده شیفت‌ها و امکان صف عکس را در قطع ارتباط حفظ می‌کند. اگر شیفت پیش از دریافت عکس نهایی شده باشد، سرور عکس جدید را رد می‌کند و اپ دلیل را در صف نشان می‌دهد. موقعیت سرور هفت روز نگه داشته می‌شود و نمایش زنده پس از ۹۰ ثانیه بدون نمونه به‌روز، «آخرین موقعیت» را نشان می‌دهد.

## اجرا و ساخت

Node.js 22.13 یا جدیدتر، npm و Go/PostgreSQL پروژه را آماده کنید. ابتدا API را با نسخه جدید اجرا کنید تا مهاجرت دیتابیس انجام شود. در دستگاه واقعی، نشانی سرور باید از دستگاه قابل دسترسی باشد. نسخه‌های توزیع از HTTPS استفاده می‌کنند و مقدار `EXPO_PUBLIC_API_ORIGIN` فقط نشانی عمومی است.

```powershell
cd mobile
npm ci
npm run typecheck
npm test
npm run bundle
$env:SAMPLING_LOCAL_BUILD = '1'
npm run android
```

`SAMPLING_LOCAL_BUILD=1` فقط برای تست اندروید با HTTP محلی است. شبیه‌ساز اندروید به API روی ویندوز با `http://10.0.2.2:8080` متصل می‌شود. برای اجرا باید یک دستگاه یا شبیه‌ساز متصل باشد. قابلیت موقعیت پس‌زمینه به build بومی نیاز دارد. [تنظیمات بومی Expo Location](https://docs.expo.dev/versions/v55.0.0/sdk/location/)

برای ساخت APK آزمایشی روی ویندوز، پس از نصب JDK و Android SDK، این فرمان‌ها را در پوشه `mobile` اجرا کنید. قالب محلی Expo فایل `android/app/build/outputs/apk/release/app-release.apk` را با کلید آزمایشی می‌سازد. [ساخت بومی با Expo](https://docs.expo.dev/guides/local-app-production/)

```powershell
$env:SAMPLING_LOCAL_BUILD = '1'
npx expo prebuild --platform android
.\android\gradlew.bat -p android :app:assembleRelease
```

برای تست روی گوشی اندرویدی متصل با USB و USB debugging، `adb reverse tcp:8080 tcp:8080` را اجرا کنید و در صفحه ورود، نشانی `http://127.0.0.1:8080` را وارد کنید.

برای نصب آزمایشی با EAS، یک بار پروژه را به حساب مالک متصل کنید و پروفایل `preview` را بسازید. اگر `eas init` درخواست تنظیم دستی کرد، شناسه‌ای را که چاپ می‌کند در `expo.extra.eas.projectId` داخل `app.json` وارد کنید. EAS برای Android فایل APK می‌سازد. نصب داخلی iOS به امضای Apple Developer و ثبت دستگاه در پروفایل توزیع نیاز دارد. اجرای شبیه‌ساز iOS به macOS و Xcode نیاز دارد. [ساخت و توزیع داخلی با EAS](https://docs.expo.dev/build/internal-distribution/) و [تنظیمات پویا در Expo](https://docs.expo.dev/workflow/configuration/)

```sh
cd mobile
npx eas-cli init
npx eas-cli build --platform android --profile preview
npx eas-cli build --platform ios --profile preview
```

فاصلهٔ درخواست موقعیت در Android روی ۳۰ ثانیه است. در iOS زمان تحویل با Core Location تعیین می‌شود. وظیفهٔ مکان در پس‌زمینه برای دریافت نمونه‌های پس از ناهار ثبت می‌ماند و اپ دادهٔ مکانِ ناهار را کنار می‌گذارد. نشانگر سیستم‌عامل ممکن است در استراحت دیده شود. بستن اجباری اپ، محدودیت باتری و مجوز مکان می‌توانند فاصلهٔ واقعی را بیشتر کنند. در نبود مجوز پس‌زمینه، اپ وضعیت ثبت در حالت باز را نشان می‌دهد. [رفتار موقعیت در پس‌زمینه](https://docs.expo.dev/versions/v55.0.0/sdk/location/#background-location)

## به‌روزرسانی درون اپ

اپ هنگام باز شدن، بازگشت به پیش‌زمینه و اتصال دوباره به اینترنت، نسخهٔ سازگار را بررسی می‌کند. هنگام استفادهٔ پیوسته، بررسی زمان‌بندی‌شده هر ۱۵ دقیقه انجام می‌شود. دکمهٔ «بررسی نسخه» هم در صفحهٔ ورود و پایین فهرست شیفت‌ها در دسترس است. دانلود سازگار خودکار است و وضعیت دریافت و درصد واقعی نشان داده می‌شوند. اعمال نسخه تا بستن فرم شیفت و توقف اشتراک موقعیت صبر می‌کند. صف موقعیت و عکس روی دستگاه باقی می‌ماند.

یک بار با تنظیمات جدید، نسخهٔ بومی آزمایشی بسازید و نصب کنید تا `expo-updates` و کانال `preview` روی دستگاه فعال شوند. شناسهٔ پروژه باید هم هنگام ساخت و هم هنگام انتشار به‌روزرسانی در دسترس باشد. در اجرای CI می‌توان `SAMPLING_EAS_PROJECT_ID` را در محیط ساخت و انتشار تنظیم کرد. ساخت محلی با `SAMPLING_LOCAL_BUILD=1` به کانال انتشار متصل نمی‌شود. [کانال‌ها و نسخه‌های سازگار Expo](https://docs.expo.dev/eas-update/deployment/)

```sh
cd mobile
npx eas-cli update --channel preview --environment preview --message "Update field app"
```

برای آزمون روی دستگاه، یک اصلاح کوچک سازگار مانند تغییر متن منتشر کنید. اپ را باز کنید و بررسی کنید که دریافت انجام شود و پس از پایان کار جاری، نسخهٔ تازه باز شود. بعد از آزمون، کانال `production` و محیط `production` را برای ساخت و انتشار اصلی به کار ببرید. تغییر کتابخانهٔ بومی، مجوز یا SDK به فایل نصب جدید از مسیر توزیع اپ نیاز دارد. پیش از انتشار، قواعد فروشگاه مربوط به نوع تغییر را بررسی کنید. [انتشار به‌روزرسانی سازگار](https://docs.expo.dev/eas-update/introduction/)

## گفت‌وگو، تاریخچه و نقشهٔ کمپین

از بخش **کمپین‌ها** یک کمپین را باز کنید. تب **گفت‌وگو** پیام‌های متنی تیم همان کمپین را نمایش می‌دهد و تب **تاریخچه** رویدادهای ثبت‌شده آن را نشان می‌دهد. سرپرست می‌تواند در **نقشه تیم** موقعیت‌های شیفت‌های خودش در همان کمپین را ببیند. پس از پایان کمپین، پیام‌ها و تاریخچه همچنان در دیتابیس سرور در دسترس‌اند. برای دریافت یا ارسال پیام و باز کردن تاریخچه اتصال به سرور لازم است.

صفحهٔ نقشهٔ داخل اپ از داده‌ها و فایل‌های محلی MapLibre روی همان API استفاده می‌کند. «باز کردن نقشه» نقطه را داخل اپ نمایش می‌دهد. برای بارگیری نقشه، گوشی باید به سرور پروژه دسترسی داشته باشد. [آماده‌سازی نقشهٔ خودمیزبان](../docs/iran-map.md)
